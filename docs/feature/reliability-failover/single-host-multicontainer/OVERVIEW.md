# 单主机多容器实例高可用 — 概念与边界

## 场景与承诺

同一主机启动两个应用容器，服务相同两个租户/Bot，共用权威数据库、队列及协调域。一个应用实例非优雅退出后，存活实例通过稳定callback入口、工作回收和原投递账本继续承担职责；恢复退出实例后可重新加入，再测试反向故障。

应用实例并非按Bot固定一一绑定，也不是两个互不共享数据的完整环境。WeCom为HTTP callback，入口与后端健康负责接入，Worker会话执行权和Delivery segment权分别竞争；没有Bot长连接主节点迁移协议。

## 三个具体数字

| 当前值 | 含义与边界 |
|---|---|
| 1台主机 | 故障域仅到单应用进程/容器；不证明整机容灾 |
| 2个应用实例 | 当前Compose的A/B布局，共享两租户工作；不是容量结论 |
| 默认30秒 | 应用全局优雅排空期限；SIGKILL不走排空，不是自动接管RTO |

## 哪些共享、哪些隔离

共享PG保存输入、计划、SDK状态、结果及投递；同环境Redis保存流和租约。每实例有独立InstanceID、每次启动有随机ProcessStartID，所有角色owner带启动代次；容器网络端口和/tmp隔离，技能版本按不可变内容只读共享。秘密目录可以各自私有，但原秘密材料与版本必须可解析。

稳定入口默认宿主58087，A/B诊断端口58088/58089，容器内都可用8080。具体端口可配置，不能把“同容器端口号”当成宿主端口冲突。

## 重新加入与停止

新实例先核对依赖/配置/技能/秘密，工作角色真实访问队列后才ready；入口按连续成功阈值恢复路由。旧进程剩余写入不能绕过原Fence/claim版本。SIGTERM先关闭准入和新消费，保留活动工作有限排空，超时交给可靠恢复；SIGKILL直接依赖回收。

## 范围与不包含

PG/Redis、唯一稳定入口、宿主内核/磁盘/电源或外部模型/渠道整体故障独立判断；容器自动重启、存活实例接管和计划排空是不同机制。低流量成功不证明单实例峰值容量或长期负载稳定，ready也不证明一个具体任务已完成。
