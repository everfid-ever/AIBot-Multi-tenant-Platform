# 在途任务接管与幂等投递 — 概念与边界

## 场景与承诺

原输入已可靠接收但尚未完成最终回复时，执行/发送节点退出，存活节点沿原request自动回收工作，复用可信结果，补做可安全完成的部分。用户无需重新发同一消息；模型可重新调用，不要求恢复生成中途的内部状态。

保护对象同时包括任务进度、工具外部效果、公开结果、原最终回复及租户归属。未知副作用或不确定投递不是成功；无法安全继续时应持久失败/审计处置，不能盲重放或换键掩盖。

## 三个任务预算数字

| 当前默认 | 含义 |
|---|---|
| 8次 | 原任务最多8个新模型运行机会；一次机会内部可有多个模型逻辑/HTTP调用 |
| 3次无进展 | 只有新增已验证成功步骤才重置停滞；改标题/重启不算进展 |
| 1800秒 | 从原StartedAt计算的固定整体任务年龄，不随重试延长 |

这些不是RTO、吞吐或最多只发8个HTTP请求的保证。Worker尝试、模型调用、工具尝试、实际效果及客户端回复分别统计。

## 当前实现的业务故事

原输入→可回收工作→lease/Fence→原目标/计划/步骤→可信工具结果与适用读回→完成条件校验→加密完成候选→原治理结算→公开结果→terminal/Outbox→原分段投递。已有候选不重生成答案，已有回执不再次发送；同键不同内容、原结果冲突时保留证据失败。

具体笔记场景已接入明确 `/note` JSON：冻结原参数，创建仍须用户确认，写入后独立读回，最终答案引用真实编号。普通自然语言任务只受已有计划与明确配置条件约束，不自动获得完整语义正确证明。

## P1至P4与外部边界

| 窗口 | 恢复方向 |
|---|---|
| P1 已持久接收未执行 | 数据库工作/Outbox/Redis pending回收原输入 |
| P2 模型或工具执行中 | 回收执行资格；模型可重试，工具按原键查询/幂等或manual停止 |
| P3 结果与待发已提交 | 原Outbox/冻结内容继续投递，不重做业务 |
| P4 渠道已接受但本地未确认 | 有匹配持久回执只补sent；无回执时须可靠渠道查询/去重或外部证据处置 |

当前WebUI可按完整目标与请求键核对邮箱；WeCom/飞书代码没有通用可靠请求键查询，不能无条件承诺每个输入恰好一次可见。code_exec仍manual，其他业务工具需逐个审核幂等/读回契约。
